# Ordinary FES platform frontends

The default World kind34 factory creates FESCoordinator. Only its normal-command route handles the installed names `clipboard`, `config_open`, `fontcom`, and `opensite`. Per-object dispatch and the legacy fixture player are separate consumers.

`clipboard` expands its first existing token once, ignores later tokens, and queues the unchanged narrow C-string bytes. Missing first token returns0. `opensite` expands first and optional second once; second is read only if first exists. A present second yields exactly `first + "://" + second`. It does not evaluate a URL, normalize a path or join extra operands. `config_open` reads no operands. The three valid queued routes return-3 through the existing interpreter flush state; no script result variable is written. Both ABIs retain their existing quoted-token behavior.

One coordinator `pendingRecords` FIFO holds these semantic records alongside Draw/base-image work. Host actions execute only during its normal drain. Current payloads own plain Uint8Array bytes. Completed actions and clipboard contents are not stored or replayed. Snapshot refuses a currently awaited platform action; unconsumed records remain in this existing queue. Closing the FES owner discards its queue, releases its enumeration and cancels suspended continuation without setting a script EXITCODE. Its coordinator exposes the one frontend closed flag through a read-only view; explicit commands on a closed runtime fail, while an already suspended run ends as cancellation. No additional queue, checkpoint version, history or default-settings copy is created.

The clipboard consumer opens the application's existing virtual window owner, ignores an EmptyClipboard false result, writes CF_TEXT's CP932 text view without changing literal backslash-n, and finally closes a successfully opened clipboard. Open failure skips the remaining operations. After awaiting open or empty, a closed owner starts no subsequent empty/write. A successfully opened clipboard is still closed in finally. An empty/write already issued to the platform may complete after close and cannot be rolled back. The existing BrowserNativeClipboard reports real availability/permission outcomes; authored Node providers never touch the system clipboard.

`fes-open-site` is an explicit `world.window.action` boundary carrying exact bytes and FES owner. A host must return its actual unsigned ShellExecute result. Success is greater than32; selected errors0/2/3/5/8/11/26/27/28/29/30/31/32 use the existing localized global-string/messagebox boundary. Other codes<=32 do not show a dialog. BrowserNativeWindow has no external-open implementation yet; it raises an explicit unsupported-action error. After an awaited external-open result, a closed owner does not create a new error dialog. An already opened owned error modal shares the existing owner-close cancellation path. No stub result or automatic browser navigation is installed.

`fes-configuration` uses the existing BrowserHost configuration working copy. Apply commits the active NativeConfiguration through its existing FES configuration service and persistence path; cancellation leaves it unchanged, and the true default Settings source is untouched. Its existing single modal carries the FES owner so close cannot dismiss another owner's dialog. The same unreleased fes-owner-close action replaces the former configuration-only cancel name in place. The actual Host refuses a late owned modal for an absent/releasing owner. A canceled asynchronous draft cannot apply after that modal closes. This browser UI exposes the existing recognized Message/Audio/Effects/Window/Text-and-language controls. The traced Game76 PropertySheet starts with one page and dynamically adds further pages based on active flags; its exact page tree, help/export visibility, system-information presentation and reinitialization behavior remain Phase8 work. SDK74's queued message0x465 is proven; its detailed PropertySheet page tree is not inferred from Game76. The browser mapping does not claim visual/page equivalence.

`fontcom` supports exactly case-sensitive `init`, `count`, `get`, `search`, `default` and returns0. It owns one optional enumeration per FES interpreter. Init releases the previous list, then enumerates the shared platform family catalog twice using the captured active proportional flag, charset128, TrueType flag and nonvertical full-name filter. Shared pure catalog helpers preserve the existing Windows adapter's family order/dedup and64-unit full-name fields. The second pass resets and determines the final count; a smaller list creates no unwritten empty slots. SDK names retain narrow bytes; Game names retain UTF16 units, with query output converted through the existing CP932 encoder.

Uninitialized count/get/search/default read no output operands. Count evaluates one existing output index. Get evaluates an existing item index before reading its existing string destination; unsigned out-of-range writes an empty string. Search evaluates its output index, then reads the raw command tail after the third ASCII space, with no bank/SCRIPT expansion or quote processing. A missing tail, including when the third space is immediately followed by the terminating NUL, writes nothing; case-sensitive lookup returns first index or-1. Default evaluates its existing destination and then calls `world.nativeDefaultFontBytes()`; the provider represents true default Settings, never active font.name. Layout font/fontind instead use current Settings and are not this provider's consumers.

The real loaded-font metadata mount remains Engine.createNativeWorld's bootstrapOwner.fontFamilies→CanvasRenderer.nativeFontFamilies. An explicit synchronous host.nativeFontFamilies(world) can supply that same catalog boundary. These are real loaded-font data, not an assertion that browsers enumerate all host OS fonts. The existing defaultSettings/configuration-memory data view can lend the default font; a missing default view/provider is an explicit D8 dependency. Phase8 owns the true default tree and complete host font discovery.

The queued wrappers' original1024-byte token temporaries allow at most1023 non-NUL bytes. Their independent2048-byte allocation allows at most2047 bytes plus NUL; the separate20-byte native record header consumes no payload capacity. Full fixed-size native memory copy is not a string truncation rule. The JS boundary rejects overflow instead of emulating undefined native writes or capturing uninitialized padding. A second font pass growing beyond the first allocation is also refused. These are explicit JS safety limits, not native overflow equivalence, and do not change ordinary resource-name ABI.

The one ephemeral inFlight context is installed before the first Host invocation, including a provider's synchronous close callback. It records only the current operation/modal/promise for cancellation and snapshot refusal; none is serialized. Owner close requests existing modal cancellation without awaiting the original Host promise, avoiding a reentrant provider→close→same-promise cycle. Already initiated nonmodal requests settle naturally; pending requests continue to prohibit snapshots. No second scheduling queue, shadow lifecycle state or fabricated external success is introduced.

An already issued Host request rejected after owner close is abandoned as cancellation; a live-owner transport failure still propagates. Explicit new execute/command calls on a closed runtime reject before evaluating its bank expression. The suspended continuation itself stops without a fatal or script EXITCODE.

The FES task adapter captures the current player for one tick and checks the same live player after input, player-step and synchronization waits, before further synchronization or EXITCODE access. A task/World tick whose FES owner closed during its Host wait ends normally; it does not dereference the released player. The general World scheduler is unchanged.
