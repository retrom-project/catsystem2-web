# Startup Blowfish primitive

`src/native/startup-blowfish.mjs` exports `StartupBlowfish`. It owns one private
P18/S1024 key schedule and exposes only `decryptInto` and `decryptResource`.
Its private encryption core serves the 521 schedule expansion steps; it is not
a public encryption API. The module performs no I/O, randomness, clock access,
ABI selection, task registration, author decision or startup validation.

`new StartupBlowfish(effectiveKeyBytes)` accepts a Uint8Array or Buffer with
1–511 bytes. All bytes, including zero, are significant. The key word grouping
is big endian, cycling through the provided length for 18 words. Therefore a
key longer than 72 bytes uses only its first 72 bytes. A 56-byte modern-library
limit is not imposed. An empty effective key diagnoses the original undefined
zero-length schedule; key lengths above 511 and non-byte inputs are rejected.
This primitive does not XOR KEY_CODE bytes or stop at the first NUL. Those
resource-to-effective-key operations belong to its future startup caller.

`cipher.decryptInto(source, destination)` reads each 8-byte block as two LE32
words and writes the two LE32 result words independently. There is no IV, CBC
state, padding insertion/removal or text decoding. It returns the processed
byte count. Empty input or a non-8-byte-multiple returns 0 without writing any
destination byte, including a complete initial block of a misaligned payload.
Aligned input requires sufficient destination capacity. Exact same-offset
in-place and disjoint byte views are supported; unproved partial overlap is
explicitly rejected before writing. Source and destination must be Uint8Array
views; non-byte coercions are not part of this interface.

`cipher.decryptResource(source)` returns independently owned plain Uint8Array
storage of `source.length + 8`, initially zero. It ignores the low-level return
value as the original caller does. Misaligned input therefore returns an all
zero buffer, rather than a strict size error or partially decrypted prefix.
For aligned input, bytes after the input length remain eight zeros; existing
NUL bytes and padding-like plaintext bytes are preserved. This does not define
V_CODE resource load/size errors or C-string comparison, nor write private
Settings slots. Those remain separate consumers.

The 16-round structure and every one of the 1,042 initialization words were
checked against the original Game static cipher/table, using the public
designer-provided pi data as the product source. This was static evidence,
with zero original execution. SDK lower-level equivalence remains unknown:
there is no consumer/ABI enablement for either profile in this leaf.

Normal Node tests load small factual records from
`tests/fixtures/startup-blowfish/vectors.json`: 34 official known answers and
14 authored cases generated by one independently compiled original-author C
reference. These cover 1/55/56/57/71/72/73/511-byte keys, high bits, embedded NUL,
multiple independent blocks, NUL tails and padding-like data. The C reference's
unsigned-word/character portability adjustments retain its rounds and key loop.
Normal tests need no compiler, executable, key resource or local research data.
