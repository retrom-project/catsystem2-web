# Native FES task protocol

SDK23 Main449/450/451/647 now have normal factory-loaded Script/FES and
retained-Draw consumers. The caller establishes Main260 output coordinates and
writes the complete borrowed Draw bitmap before wake can force-copy it. ALT and
missing-label replies, the `_SAVEOBJ_` value, delayed Root decoding, replacement
attachment and native retirement are distinct from physical GPU presentation.
Earlier local runs missing the Draw-output initialization remain unqualified;
their successful native returns do not establish initialized pixels or offsets.

The SDK23 sleep receiver masks its retained resources and redraws on wake; it
does not invoke `_FES_SLEEP_` or `_FES_WAKE_`. Its own raw313→425900 body and a
loaded source with both handlers prove that private0 remains0. The Web path
previously fired the wake handler and wrote222. SDK63 retains its existing mask
policy. SDK67 and ee6-76 explicitly call these labels in44b160/62e1b0 and keep
that behavior. Independently, the23/63/67 sleep receivers return0 while ee6-76
returns1, with no reply-scratch store. Main647 consumes that transport status and
still returns control2 with no VM value. Current checkpoints cover both axes;
the extra63 contrast uses a normal owned Main71 carrier because Main65 remains
protected on that build.

Main649/650 operate on the currently selected private bank. The SDK23 ordinary
positive uses a real FES `execkcs` child, whose normal loader registers an
inherited Script context. Its2048 initialized bytes are copied to an owned CSS
record, changed, restored, consumed by later VM reads, and released before the
child and FES retire. Missing records return0. This does not qualify an absent
private context or raw address access. Four independent current checkpoints
cover live CSS, restored words, child retirement and final owner cleanup.

`createNativeFESTask` owns one FES interpreter, its private variable context,
string-bank reference, retained surface, display state and image-data cache.
KCS calls use task messages through the World's Top-scoped router. They do not
call a menu selected by a game filename. The complete original task handler is
still being audited; this document distinguishes the implemented message
contracts from the remaining controls and parser work.

For the pinned 2.6.1.23 build, loading a FES borrows the sending Script's
variable bank. It does not acquire ownership of that bank. Each interpreter
registers its own 512-word private context and named values. Two FES instances
can share the supplier while keeping those contexts separate. Reinitializing
one interpreter starts fresh private words, named defaults and result state;
the other instance retains its state. Normal retirement unregisters the FES
context while the supplying Script and bank remain alive.

Main665/666 copy only when the actual caller has a registered private context.
A Script with its own initialized bank need not have the inherited context
that a child Script registers during Main143 loading. In that absent-context
shape the original calls are defined no-ops. Calling the wrappers or observing
unchanged words does not prove a successful copy. The inherited-caller copy
contract remains distinct from this shape, and names are not word storage.
Current internal checkpoints retain the actual interpreter contexts and
continue their loaded programs without rerunning notifications. This does not
add anything to the original GAME_SAVE/CSS file layout.

For a Main143-loaded child Script that actually inherits its parent's bank,
Main665/666 copy the fixed 512 private words between that Script's registered
context and the current FES interpreter. The word storage is copied, rather
than aliased; subsequent callbacks change the FES words without changing the
saved Script words. Named storage remains with each context. Rebuilding a FES
creates fresh defaults before an explicit copy, and a later FES lifetime does
not reuse its predecessor's private state. Retiring borrowing FES instances
before the child Script unregisters both levels while their supplier remains.

Original frame probes must match their dispatch scope. A selected Script
subtree update does not run an ancestor Top's null-route sweep. Present-null
keys still reserve native IDs until that Top is updated, so a later factory can
receive a different ID and child traversal position from a complete World tick.
Both paths use the same internal update traversal; this is no ID-allocation
policy change or public runtime/checkpoint API. A retired object is not a valid
sampling target, including when a later-created FES retires later in the same
parent walk that delivered its close request.

The original FES first-update input setup walks to a real kind1 Top ancestor.
Calling the Top constructor alone leaves the Base kind and is insufficient
for this dependency. The original application controller initializer creates
both its View and Top and writes that kind; the corresponding controller
disposal owns both objects. Test hosts must preserve this ownership and close
borrowing FES instances before their supplier Script. A supplier-first native
destruction boundary is not a successful lifecycle result.

Normal runtime block reads copy the current source-bound string bank expansion
into owned working bytes, then apply registered source macros once. They do not
apply whole-row SCRIPT replacement, split inserted bytes into new rows or mutate
the stored program. Already prepared inline execution retains its current copy
and offset without repeating either stage. Operand getters keep their separate
bank/SCRIPT boundaries; a macro may emit a placeholder after the row-bank pass.

When token zero is missing, a frame advances its existing PC and uses the native
positive-one return to resume on the next frame. An event instead stops that
label's row loop: a DEFAULT handler can still be followed by the object's own
handler. Null-object notifications and event continuations after an asynchronous
flush use the same event mode. They do not introduce a frame delay or retain the
event's trailing rows. Checkpoints preserve stored rows and actual working-copy
addresses without running either expansion stage during restoration. Bare FES
players retain their independent source contract. Command-head SCRIPT ordering,
conditional/skip and other parser parity remain separate audit work.

When the normal default route selects an existing collection object, its verb
uses the existing byte-first bank/SCRIPT getter once. A missing verb returns0
without a getter; a present verb that expands to empty still runs that getter.
Built-in dispatch keeps its existing result and explicit implementation limits.
A custom verb with no definition records a diagnostic and returns0, allowing the
same event to continue. An unmatched object reference retains its current
routing boundary. The selected raw name/index and complete working command copy
remain the source of native addresses; checkpoints do not replay the getter.
This object-verb stage preserves the separate command-head, object/common
priority and conditional gates.

The normal interpreter owns the event's raw name bytes, signed index and evaluator
current value independently of its typed object. Construction starts with an empty
name and zero words; frames do not reset them. Ordinary DEFAULT and own handlers
use the actual collection group's bytes and index. Message337 copies its original
name bytes: a NULL name clears both words, while a non-NULL empty name retains its
incoming index and current value. A missing typed object does not discard this
context. The original label bytes remain separate from the context name.

Each normal event saves and restores the complete tuple, including nested
notifications and its existing asynchronous command continuations. Explicit
property and motion evaluator current values, including zero, keep priority over
the event current value. Normal checkpoints require and copy the current tuple at
the existing settled frame/wait boundary; restoration does not replay source,
events or resources, or serialize a pending Promise. Bare evaluator semantics,
the separate GCALL notification producer, command-head parsing, object/common
ordering, conditional/skip and native overflow gates remain separate work.

The configuration event uses the registered ABI's
`fes.configurationMessage` stages. The reviewed Game receiver visits the current
object-key map first, calls each live image configuration callback, notifies
`MES_CHANGECONFIG`, then traverses its saved resource FIFO. The reviewed SDK
receiver enters that FIFO directly, with neither the live-map stage nor that
notification. This event does not select a private variable context by itself.
World preference-persistence dirty remains a separate flag.

The event captures its current player/runtime/owner only on the call stack.
After notification and each awaited sound callback, it checks the same player,
closed runtime, and releasing/removed owner before continuing the FIFO. The sound
185 callback checks that same call's predicate after its query and before new
pending-play writes. Already issued queries and pre-close dirty writes are not
rolled back. A failed in-flight request is canceled only after that owner loses
liveness; live request failures still propagate. No predicate, cancellation
state, queue or continuation is added to the checkpoint.

The Game live-map callback applies to IMAGE, BUTTON, PANEL, SAVEPANEL, BGTABLE,
BGTABLE2, CHTABLE, CHTABLE2, CHTABLE3 and IMGWND. Other recovered constructible
families have a proven empty callback; NUMIMG has no object. The map uses its
original current key order, independently of the resource FIFO and lifetime
handle order. Each image owns narrow `fileSourceBytes` (SOURCE) and `fileBytes`
(CURRENT), once each. The existing BGTABLE/BGTABLE2 CURRENT bytes remain the same
authority. Its `file` string is a non-enumerable CP932-derived view.

A FILE definition or admitted `load` argument performs its existing bank/SCRIPT
expansion once and writes original narrow bytes to SOURCE. A CGL selection uses
the already selected exact bytes. No target-class encoding is applied. The
callback starts CURRENT from saved SOURCE, replaces `%LANG%` with the selected UI
prefix (or valid default), then replaces `%LANG_M%` with the main prefix (or valid
default). A missing selected/default row leaves that marker unchanged. Only the
Settings wide prefix crosses its defined CP932 conversion boundary. A table
selector writes CURRENT alone; a configuration event never reselects a table,
re-expands FILE, or reads the source resource again. Checkpoints save these two
semantic fields once and restore without replay.

The image comparison supports the verified normal C-locale initialization and
creation flow of this frozen Game ABI. It folds each original ASCII byte A..Z,
including bytes inside CP932 sequences, and sets image-changed only when that
comparison differs. It still updates CURRENT for a case-only change and never
clears an earlier change request. Normal JS startup/FES APIs have no locale
mutation/import path and do not borrow an unknown native CRT flag. Non-C or
unverified locale consumers remain unsupported and require their own reviewed
route before entering this callback; this is not a general CRT locale model.
Overlong filename/prefix results beyond the defined 256-byte CString fields
remain explicit unsafe-boundary diagnostics.

The FIFO dispatches by each entry's saved raw type, then resolves its current
name/index. Missing current objects are skipped; duplicate entries retain their
order. SOUND/SNDTABLE use their existing common sound service. STRING,

independently refresh only the enabled fixed-pitch, face, weight and shadow

SDK narrow bytes or Game UTF16 units, without a CP932 round trip for Game.
Callback copying preserves destination padding and diagnoses unterminated or

Saved non-text/non-sound entries have a proven FIFO default no-op even when the
current key names text. Same concrete type/ABI rebinding and SOUND/SNDTABLE

The `result` script command stores a signed 32-bit expression and yields through
the native -3 processing path. Private context contents and names live once in
`NativeVariableBank`; the FES checkpoint records their identity. The per-FES
image residency map stores only explicitly inserted/preloaded data-buffer
pointers into the one shared process checkpoint. Lazy `imageData(name)` results
are caller-owned: each miss reads a distinct descriptor without becoming
resident, and each resident hit retains a temporary reference. The caller must
return that reference. Decoded bitmaps own their independent data; current IMAGE
frame maps retain their encoded descriptor in existing object state. Fresh
restore neither rereads held bytes nor inserts them into residency. Closing an
interpreter unregisters its private context before releasing its objects;
closing its task then releases resident-map references, followed by base/child
disposal. Unsettled source I/O rejects a checkpoint or cache close.

Successful message332 initializes definitions, then consumes the source's real
`#PRELOAD` section before allocating resource entries. Each nth getter starts
at raw section index0, including the section header itself, and repeats this
scan even for its final EOF attempt. A header requires raw byte0 to be `#`;
prepared leading spaces do not create a section. Repeated headers append to the same section.
Plain input uses the existing source cleanup; prepared input preserves each
whole byte line, interior blank, space and tab, without token or quote reduction.
A terminal newline creates no synthetic trailing row.

The load captures the actual already-bound string bank, without creating one.
Every visited raw row expands against that same bank's current bytes before
checking whether byte0 is `#`; an expanded-empty row is still a row. This getter
uses neither the argument/SCRIPT service nor language or macro replacement.
Each selected CString passes through the existing non-text resource-name ABI
and `FESImageCache.preload`: real image-category search mode3 reads precede
first-win insertion, including duplicate names. Empty files can own a zero-size
descriptor; missing files do not terminate the section.

The native getter's512-byte scratch receives a direct bank expansion with two
NUL bytes (at most510 semantic bytes), or a no-bank copy with one NUL (at most511).
It does not copy the raw source into that scratch before expansion, so a longer
raw line can safely shrink through its bank substitutions. The selected filename
then copies one NUL into its260-byte destination (at most259 semantic bytes).
Crossing those original unbounded-write domains is an explicit diagnostic,
without truncation, rollback of earlier reads or a new general resource limit.

These raw rows stay in the existing program checkpoint; there is no PRELOAD
cursor, replay flag or second residency owner. Reinitializing an interpreter
preserves its Task map; an explicit new332 load repeats the source reads, while
fresh restore rebuilds held/current/map references without source or bank replay.
