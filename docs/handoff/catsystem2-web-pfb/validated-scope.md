这些是 5509 个唯一 `build/table/id`，包含未证明、桩和 guard；**不是 5509 个通过项**。Main 编号有构建差异；MOT/Generic 和两张 PTCL 表有独立 typed receiver、参数和控制返回，Main 的通过不能自动替代它们。旧 9.5MB 库、W55 与 W67 thin5509 是基线，后续用已封覆盖差量叠加，不重生总库。

| 分类                                      | 能说明什么                                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| functional / finite                       | 已证明的正常有限参数、typed owner、真实 caller/control/return/副作用和适用寿命；不包含未测域或所有 backend。 |
| original-stub                             | 完整原 wrapper 本来就是桩；不是 Web 缺陷，也不是实际功能消费。                                               |
| receiver-ignore / original-empty-receiver | 原 receiver 对该消息忽略或合法空结果；不能提升成非空业务通过。                                               |
| guard-only                                | 只证明当前拦截/拒绝形态正确，不证明正常功能已实现。                                                          |
| unproven                                  | 缺合法 producer、初始化、调用方、原上下文、消费或宿主依赖；已登记也可以仍未证明。                            |

运行时的 recovered/reserved/constant-zero/unknown 是登记分类，独立于上述功能证据。不能用 registered、静态没有调用或扫描相似消除缺口。共用 Web 缺陷修公共实现；只有原版完整函数体和相关调用上下文证明差异才建版本策略。未知构建、任意 unknown span、未写域和未证物理布局继续 guard。

同 exact PE 的其他游戏可以复用已证明函数体与 typed 上下文组；仍须核 authored KCS、资源类别、参数/对象布局和内容差量。Koi1/Koi2 共用 .74 构建及相同 KCS 时可按 hash/context 去重，不能省略各自特有内容和存档行为。wrapped `638e…` .76 不在 plain `ee6…` 准入内。

## 已采用与 source-only

活跃 `0e9b` 的接受根明确列出已集成 W63/W64/W69/W71，以及此前 Clock、Task/FES、内存复制和最终资源退休等生产差量；W57/W59/W65–68/W70 的 0prod 证明按原范围复用。W72 为有限 exact63 FES named/private 资格。W73、W74、W75、W76 是已接受但尚未切入的独立生产后继，详见发布准备。不能从联合 HEAD 拼出一个“已验收版本”。

所有资格保留原 CRT/allocator、primary Sound source、局部 carrier、虚拟 Win32/FileServer、Window/DOM/COM-memory 端口限制。软件 canvas/SwiftShader 小图、纯 COM-memory Present 记录、真实 UHD Stage 和物理扫描输出是不同证据；本目录不将其互换。
