# Native preference XML

`serializeNativePreferences(configuration, { flags = 3 })` produces the original preference-file bytes. `applyNativePreferences(configuration, bytes, { flags = 3 })` validates the profile's XML and applies it through `NativeConfiguration.applyUserPreferences`; an invalid document returns `false` before changing configuration. Persistent storage and dirty-write scheduling belong to the world/platform layer.

Both original constructors default to `setup.xml`. The game stores this UTF-16 name at engine-owner `+0x208`; the SDK stores the CP932 name at `+0x104`. The original read/write wrappers join that name with the expanded startup `FOLDER/save` directory (`+0xF84` game, `+0xA70` SDK). The frozen game's authored directory is `%USERPROFILE%\NEKO WORKs\nekopara3`. Browser storage maps this location into its content-isolated namespace while retaining the XML bytes and file name.

Flag 1 writes system settings: WINDOW, TEXTURE, SOUND, ETC, DEPEND, D3D, FULL_SCREEN and, in the newer engine, language. Flag 2 writes CONFIG, FONT, KEY, VOICE, MESSAGE, EFFECT, GAME and SYSTEMVOICE. The complete 80-row key loop writes six four-byte binding groups for enabled rows; touch and repeated-touch groups are not preference fields. Voice and system-voice flags each contain 48 rows. The original reader intentionally omits several writer fields, including cache, full-wide and the two depth preferences. These asymmetries are preserved.

The game emits UTF-8 and the SDK emits Shift_JIS. Both serializers use CRLF, two-space indentation, explicit closing tags for empty text, signed decimal formatting for words, and the original node order. String contents are written verbatim, including XML punctuation. Consequently, some authored string values can make the original writer's output fail its own parser; the implementation preserves that observable behavior.

The recovered parser keeps entity spellings as literal text, reverses sibling insertion order, and searches duplicate siblings until a complete path matches. It consumes the first root; subsequent roots or trailing text are ignored. It accepts attributes and comments, rejects CDATA, self-closing elements and inner processing instructions, and does not expand DOCTYPE declarations. A top-level DOCTYPE is its first node, so preference lookups do not reach the following document. Native XML services and preferences share this parser.

The maintained oracle executes both original writers, their actual XML tree construction, serializer, parser, tree import and preference-reader functions. Host callbacks supply allocation, C formatting, ASCII declaration comparison, Win32 string conversion and the output-file boundary. It does not replace the XML field lookup or parser with JavaScript. The frozen executable SHA-256 is verified before analysis; the DLL characteristic changes only in an in-memory image. Public fixtures contain authored settings and XML, not engine or game code.

Run `scripts/native-preferences-oracle.mjs --exe <frozen executable> --output <ignored observation.json>` to regenerate observations. `--state-bytes` additionally records private byte-level state for debugging. Public acceptance uses `node --test tests/native-preferences.test.mjs tests/native-xml.test.mjs`.
