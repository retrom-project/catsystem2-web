# Ordinary FES system voice selection

The default World kind34 factory routes the normal commands `sysvoice` and `sysvoiceex` through FESCoordinator and a stateless JS frontend. Both return0 synchronously. They select and write an integer ID; they do not create, play, decode or wait for sound channels. SOUND.stype and playback use their separate existing services. The extension classification of sysvoiceex in the coverage registry does not change its normal installation in either frozen ABI.

The first existing operand expands bank and SCRIPT once and is evaluated once as the output index. Missing destination performs no selection. An expanded empty C-string is0 in this frontend; the general FES expression API is unchanged. The destination is captured before candidate side effects and converted to uint32 for the existing bounded variable-bank setter. An invalid destination preserves bank words while retaining the initialized bank's dirty behavior.

`sysvoice` filters the current48-slot `configuration.fields.systemVoice` and its sysplay view. A name's first byte and the flag must both be nonzero; file existence is irrelevant. Supplied candidates expand/evaluate once each and retain order and duplicates, accepting unsigned IDs0–47. Without a supplied candidate it scans all48 in ascending order. The existing flags-only native configuration random operation is a different consumer.

`sysvoiceex` first tests the existing soundConfiguration.loaded flag, before reading candidate operands. Supplied operands expand once; raw comma bytes split ID paths, and every component evaluates separately, including empty components as0. No whole-path evaluation, quote-aware comma parser or per-component bank/SCRIPT expansion is introduced. First matching siblings win; a miss retains the same level for later components. Final-step nonzero sysplay determines eligibility, with the existing ABI missing default (SDK-1, Game1). Without supplied paths, PART records are visited in preorder and only current.sysplay===1 contributes IDs. MASTER/type/group/name are not filters. Repeated and negative IDs remain candidates.

Both routes use exactly one shared `world.random.rand()` integer MT draw for a nonempty candidate list, with unsigned modulo. An empty list writes-1 without drawing. A nonempty list selecting ID-1 still draws and logs. No fresh RNG, float stream, FESPlayer random state or persistent candidate array is created.

After the selection write, an installed synchronous host.nativeDebugOutput receives owned ASCII bytes such as `select sysvoice 3`, with no newline. An absent sink has no output. This reuses the existing Host mapping; the native debug-window installation/visibility gate remains D8 work and is not claimed equivalent. No separate FES debug history, Promise, queue or awaited logging is added.

The sound tree's two dedicated read queries use its existing current parts and do not require MASTER. General find/get retain their prior strict tree requirement. The reachable current state loaded=true/master=null therefore has defined selector behavior: supplied paths use ABI missing defaults, while empty traversal yields-1. The current NativeSoundTask constructor still rejects this as startup input. Default-entry fixtures establish that current state through the same soundConfiguration.restore after valid startup; they do not claim invalid-tree startup is fixed or fabricate MASTER. Closing the FES owner reuses the existing runtime guard, without a new audio lifecycle.

The original wrapper's512-byte token temporary permits511 non-NUL extracted bytes plus NUL, both before and after expansion. The basic command's128-entry stack capacity is a separate safe limit. The JS frontend explicitly rejects overflow, without truncation or native memory-corruption equivalence; sysvoiceex's dynamic candidate lists do not inherit the128 limit. These limits do not alter resource-name ABI or the general expression engine.

Current Settings bytes, the sound tree/current flags and both RNG streams remain their existing snapshot authorities. No frontend snapshot field is added. The authored two-ABI ordinary World tests serialize and restore the existing checkpoint, read only the scheduler's fixed case.kcs once in the fresh World, and perform no FES/startup input reload or selection/log replay. They use real MT state and forbid EXE/Host playback. Their expected branches come from complete static original functions; no dynamic original equivalence or native whole-entry comparison is claimed.
